# AI 代码检视 Skill 看板设计

## 目标与受众

为团队与管理者提供一份可离线打开的静态 HTML 看板，使用 `code-review-statistics-restored.md` 的数据说明：团队正在持续使用 AI 代码检视 Skill，在提交与发布之前发现问题，并通过开发者确认与修复提高代码质量。

页面的首要任务不是罗列数据，而是形成一条可验证的成长证据链：

`团队使用 AI 检视 → 提前发现问题 → 开发者确认有效 → 反馈进入开发流程 → Skill 与团队质量共同进步`

## 信息架构

### 1. 顶部结论区

- 主标题：`把风险看在发布之前`
- 说明团队持续使用 AI 代码检视 Skill，并覆盖 6 个版本。
- 以“质量观测窗”圆弧面板展示累计检出 520、接收 214、总体有效率 41.2%。
- 用简短结论解释“有效问题”代表开发者确认有效或已修复的问题。

### 2. Skill 作用链

用静态横向流程展示：

1. AI 检视进入版本研发流程。
2. 累计发现 520 个代码问题。
3. 其中 214 个被开发者确认有效或修复。
4. 问题反馈持续用于规则与使用方式优化。

### 3. 优化进步

- 六个版本的检出数柱状趋势。
- 六个版本的问题有效率折线趋势。
- 突出最新版本 20260709：检出 166、接收 88、有效率 53.0%。
- 明确表达最新版本相较 20260625 的有效率提升 24.6 个百分点。
- 不将所有波动描述为单调进步；页面说明有效率存在版本差异，但最新版本同时实现更高覆盖和更高有效率。

### 4. 团队覆盖

- 前端：检出 175、接收 97、有效率 55.4%。
- 后端：检出 345、接收 117、有效率 33.9%。
- 使用并列条形对比说明 Skill 已覆盖不同技术栈，而非评价前后端团队优劣。

### 5. 版本全景

展示 6 张版本卡片，每张包含：

- 检出问题数、接收问题数、问题有效率。
- Critical、High、Medium、Low 数量。
- 报告数量与平均每报告检出数。
- 前端与后端的检出、接收及有效率。

卡片按日期排列，20260709 使用“当前表现”标签突出。

### 6. 数据说明

- 逐报告明细中的 20260611、20260618、20260625、20260709 为依据汇总反推的模拟数据；看板的版本级统计来自原图可见汇总。
- 原图各日期 High 合计为 358，但总计行与前后端汇总写作 360。看板按原图总计展示 360，并在页脚明确数据口径差异。
- 页面不把模拟逐报告名称用于核心价值结论。

## 视觉方向

采用用户确认的 B「质量观测站」。

### 色彩

- 雾蓝背景：`#EEF4F7`
- 观测窗白：`#FFFFFF`
- 深海青文字：`#173B43`
- Skill 价值绿：`#168C72`
- 风险琥珀：`#D58A2A`
- 辅助蓝：`#4D72C9`

### 字体

- 中文展示与正文：系统中文字体栈 `PingFang SC`, `Microsoft YaHei`, sans-serif。
- 数据与标签：`IBM Plex Mono` 风格的系统等宽字体栈，不依赖外部字体文件。

### 布局与标志元素

- 采用 1200px 最大宽度的响应式单页布局。
- 顶部“质量观测窗”使用圆弧上沿、环形有效率仪表和克制阴影，形成独特记忆点。
- 其余内容使用细边框、清晰留白和少量强调色，不重复堆叠玻璃效果或渐变 KPI 卡。
- 图表由内嵌 SVG 绘制，避免外部图表库。

## 技术方案

- 创建独立文件 `code-review-skill-dashboard.html`。
- HTML 内嵌全部 CSS、SVG 和数据，无网络依赖。
- 页面为静态展示，不提供筛选、切换或明细展开交互。
- 适配桌面大屏、普通笔记本与窄屏手机。
- 支持打印与导出 PDF 的基础排版。
- 尊重 `prefers-reduced-motion`；页面不依赖动画传达信息。

## 验收标准

- 所有核心数字与 Markdown 的版本汇总、前后端汇总和趋势表一致。
- 最新版本相对 20260625 的有效率提升正确显示为 24.6 个百分点。
- 六个版本均有完整卡片，包含严重级别、报告数及前后端数据。
- 页面明确说明 Skill 的团队使用、问题发现、开发者确认和持续优化作用。
- 模拟数据与原图口径差异有清晰、不过度抢眼的说明。
- HTML 可在无网络环境直接打开，无控制台错误。
- 375px、768px、1440px 三种宽度下内容不溢出、不重叠，关键信息层级清楚。
