# 代码检视统计看板

把固定结构的「代码检视统计总览」Markdown 转为可双击打开的独立 HTML。解析、校验与渲染由脚本完成；本 Skill 只负责触发与汇报。

## 何时使用

- 用户要生成 / 刷新代码检视 HTML 看板
- 用户提到「代码检视统计总览」「质量观测站」「检视看板」

## 工作流

1. **确认输入**  
   默认：工作区根目录 `代码检视统计总览.md`。用户指定了路径则用用户路径。文件不存在则停止并说明，不要编造数据。

2. **生成看板**（在工作区根执行；将 `{SKILL_ROOT}` 换成本 Skill 目录绝对路径）：

```text
node "{SKILL_ROOT}/scripts/render-dashboard.js" --md 代码检视统计总览.md
```

不传 `--out` 时，脚本在 md 同目录写出：

`{md 文件名去掉扩展名}-{最近版本日YYYYMMDD}.html`

例如最近版本为 `20260709` → `代码检视统计总览-20260709.html`。

用户要自定义输出时：

```text
node "{SKILL_ROOT}/scripts/render-dashboard.js" --md <path.md> --out <path.html>
```

3. **成功**  
   回报 stdout 中的输出路径与 `latest=` 摘要；需要时可打开该 HTML。

4. **失败**  
   原样报告 stderr / 退出码；**禁止**手写或修补 HTML。校验失败时脚本不会覆盖已有输出。

## 数据契约（脚本强制）

Markdown 须含：

- `## 一、各版本汇总`
- `## 三、前端 vs 后端汇总`
- `### 各版本前后端对比`
- `## 四、趋势分析`

三张含日期的表日期集合须一致；严重级别、有效率、前后端须闭合。细节见 [README.md](README.md)。

## 看板表达约束

- 最近一期必须同时展示本期值、上期值和带单位的变化说明，不能输出没有上下文的 `+N`。
- 有效率变化使用“个百分点”全称；报告数、问题数和平均值的变化不得用绿色暗示质量改善。
- Critical / High / Medium / Low 即使为 0 也要显示实际数字。
- 首屏优先容纳累计概览、最近一期、趋势和严重级别/团队构成；历史超过 12 期时折叠更早记录。
- 不要在页面展示「数据口径需留意 / 数据校验通过 / 数据口径说明」；校验仍在生成脚本内部完成，失败则不写 HTML。

## 原则

- 用脚本，不用模型直接拼看板 HTML。
- 默认路径与自动命名已足够时，不要额外发明文件名。
- 保留用户显式给出的 `--md` / `--out`。
