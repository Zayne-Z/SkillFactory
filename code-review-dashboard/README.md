# AI 代码检视月度看板 Skill

把固定结构的代码检视统计 Markdown 转换为独立、离线可打开的 HTML 看板。本目录是可触发的项目 Skill（见 `SKILL.md`）。

## 每月生成

保持 Markdown 的章节与列名不变，在三张版本表中加入新日期后，在工作区根执行：

```bash
node code-review-dashboard/scripts/render-dashboard.js \
  --md 代码检视统计总览.md
```

省略 `--out` 时，输出写在 md 同目录，文件名为 `{md 基名}-{最近版本日}.html`。
例如最近版本日为 `20260709` → `代码检视统计总览-20260709.html`。

指定输出或模板：

```bash
node code-review-dashboard/scripts/render-dashboard.js \
  --md path/to/statistics.md \
  --template code-review-dashboard/templates/dashboard.html \
  --out path/to/dashboard.html
```

## Markdown 要求

生成器读取以下固定章节：

- `## 一、各版本汇总`
- `## 三、前端 vs 后端汇总`
- `### 各版本前后端对比`
- `## 四、趋势分析`

三张包含日期的表必须拥有完全相同、不可重复的 `YYYYMMDD` 日期集合。趋势表的 `检出版本数` 会按原表含义显示为“检视报告数”，也兼容列名 `检视报告数` 和 `报告数`。第二章逐报告明细存在时，生成器会逐期核对报告行数；缺期、缺表或数量不一致时停止生成。整章不存在时允许生成，但顶部明确提示报告数未经明细核对。

生成器会校验严重级别、有效率、平均每报告检出以及前后端数据闭合。校验失败时命令返回非零状态，并保留已有 HTML。

## 展示规则

- 最大日期自动成为最近一期，并使用“本期 / 上期 / 变化说明”对比，禁止展示没有上下文的裸 `+N`。
- 数量变化使用中性色并明确单位；有效率变化写“提高/下降 N 个百分点”，不使用未解释的 `pp`。
- 首屏集中展示累计概览、最近一期、趋势、严重级别和前后端数据，不使用大幅口号或巨型仪表盘。
- 趋势图显示最近 8 期，柱形表示检出数、折线表示问题有效率，两种单位均在图例和坐标端点中标明。
- 报告数不超过 1 时显示“小样本”。检出为 0 时有效率显示为 `—`。
- 团队总体覆盖使用“前端 vs 后端汇总”章节；版本历史行使用“各版本前后端对比”。页面不展示口径差异提示。
- 原始总计与逐版本合计冲突时，累计概览仍使用逐版本可闭合合计，但不在 HTML 中披露说明。
- 最近一期的 Critical / High / Medium / Low 必须同时显示数字与比例，零值也明确显示为 `0`。
- 历史表最近一期优先，每行包含报告数、平均每报告检出、检出、确认有效、有效率、C/H/M/L 和前后端情况；超过 12 期时默认折叠更早记录。
- 移动端最近一期对比改为纵向信息块；趋势与历史只允许各自容器横向滚动，页面本身不得横向溢出。
- 输出不嵌入未使用的完整模型 JSON，避免版本很多时重复增加 HTML 体积。
